# OmniBrille v1.1.0 focus-plane correction

This is historical run evidence. Current source, tests, [`README.md`](../../README.md), and [`architecture.md`](../architecture.md) remain authoritative.

## What this run was meant to do

Correct the unpublished v1.1 visual candidate against the owner's original Light and Dark concept renders. The target was a calm focus plane: one dominant folder, a sparse readable current level, and a larger bounded universe that recedes instead of competing.

## What actually changed

Dense Structure scenes now show at most eight crisp labeled children, then 16 subdued glyphs, with the remaining admitted siblings rendered as faint point context. Secondary and ambient structural edges keep truthful connectivity but no longer receive ordinary broad glow. Selection, hover, and Search restore a receding node, its required label, and its incident edge.

The bounded scene is not pruned: the 48-node/47-structural-edge contract, navigation, hit targets, Search, graph automation, and synchronized accessible list retain the exact same node identities. The shell, provider/session ownership, Context/Hybrid data, protocol, persistence, and public interfaces did not change.

The owner-supplied concepts are now retained with hashes and a scope disclaimer in [`docs/assets/concepts`](../assets/concepts/README.md). Five real v1.1 screenshots were replaced with installed-candidate captures of the corrected Dark, Light, nested-details, Search, and accessible-list states.

## Important technical decisions

- **Decision →** Retune Structure's deterministic presentation bands to 8/16/remainder and reduce secondary/ambient edge energy. **Why →** direct concept comparison showed the shell was already close; the crowding came from 12 crisp nodes plus dozens of glowing focus-crossing spokes. **Impact →** the current plane reads immediately while the full authorized bounded graph remains discoverable.
- **Decision →** Make sparsity presentation-only. **Why →** pruning scene nodes would break navigation, Search, list/UIA parity, and the repository's bounded-truth contract. **Impact →** all admitted nodes remain keyboard-, pointer-, list-, and automation-accessible; interaction promotes receding content when needed.
- **Decision →** Keep native chrome and the existing compact shell. **Why →** the supplied concepts did not justify another window/shell redesign, and custom chrome would add DPI and accessibility risk. **Impact →** this stayed a focused renderer/layout correction.
- **Decision →** Keep v1.0.0 immutable and stop before v1.1 publication. **Why →** the owner has not authorized pushing this branch or selected signed versus unsigned publication for v1.1. **Impact →** ordinary users still receive v1.0.0; hosted qualification and release remain explicit later gates.

## Problems found

The crowded result came from two compounding presentation choices: too many high-detail Structure children and glow on every admitted structural spoke. Both were corrected without reducing graph truth. Independent review also found that a hovered non-match during Search could receive a strong edge while its node stayed dim; the policy and focused regression test now keep node, label, and edge promotion consistent. A count-only accessibility parity test was strengthened to exact node-ID equality.

No renderer, UX, accessibility, performance, privacy, packaging, or screenshot blocker remains for the local visual correction. v1.1 publication remains deliberately deferred until the owner selects its signing policy, authorizes the public branch update, and the final release commit completes hosted qualification.

## What the agents learned

- The earlier assumption that more graph visibility better expressed the product was wrong. Direct concept evidence showed that the larger graph should remain perceptible but not legible by default.
- Visual/UX, renderer/performance, accessibility/release-boundary, Documentation, Implementation, and independent adversarial review were useful for this High-risk correction. Product strategy and AX were unnecessary because product scope and AI behavior did not change.
- **Promoted:** the sparse Structure plane became executable memory through exact 8/16 layout tests, a 48-node/nine-label renderer assertion, state-promotion tests, and exact graph/list/UIA ID parity. Independent visual and adversarial reviews supported promotion.
- **Promoted:** the owner-supplied concepts became durable, hash-bound visual-direction evidence with an explicit non-product scope; this prevents future agents from rediscovering or over-interpreting them.
- **Rejected:** lower the 48-node budget or prune atmospheric nodes. Presentation-only hierarchy solved the observed problem without damaging navigation or accessibility.
- **Rejected:** add a global agent rule or ADR for this tuning. Current architecture documentation plus executable tests are sufficient and cheaper to maintain.
