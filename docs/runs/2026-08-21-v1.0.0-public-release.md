# OmniBrille v1.0.0 public release

This is a historical owner report. Current architecture and release guidance remain authoritative over this snapshot.

## What this run was meant to do

Remove Adobe DNG SDK code from OmniBrille's shipped Windows renderer dependency without accepting Adobe's terms, preserve the MIT project license and the authorized unsigned-release contract, qualify the exact application artifact, and publish the first stable release only if every release gate passed.

## What actually changed

OmniBrille 1.0.0 is publicly available from the [GitHub Release](https://github.com/nishdel/OmniBrille/releases/tag/v1.0.0). The Windows x64 installer is self-contained, per-user, MIT-licensed for OmniBrille project code, and intentionally unsigned. Its SHA-256 is `67443C616B82E066199D39EF7EDBD3DCE68B7E66BAEB26E25872E30BE0F347BF`.

No suitable DNG-free API-compatible native runtime was found among the official SkiaSharp 3.119.4 Windows packages inspected. OmniBrille therefore builds a distinctly named native package from pinned upstream source, with the optional DNG/RAW codec disabled and the DNG SDK plus RAW-only PIEX sources removed before dependency sync. The managed Avalonia/SkiaSharp API and renderer design did not change. The repository now carries the exact package, full checksum-bound provenance, target-aware notices, release gates, public README/screenshots, stable packaging, and final release metadata.

## Important technical decisions

- **Decision →** Use a project-controlled, upstream-compatible SkiaSharp native build rather than an official binary. **Why →** every compatible official Windows native package inspected contained DNG, and the owner declined its distribution terms. **Impact →** OmniBrille owns a small pinned native-build procedure and upgrade gate, but no permanent Skia fork or managed-renderer change.
- **Decision →** Prove exclusion at source acquisition, evaluated GN arguments, dependency closure, binary markers, restored runtime identity, installed bytes, and notices. **Why →** deleting a notice would not remove code. **Impact →** release validation fails closed if the official DNG-bearing asset reappears or the accepted package/native hash changes.
- **Decision →** Add `/Brepro` and `/PDBALTPATH:libSkiaSharp.pdb` to the pinned upstream Windows build. **Why →** `/Brepro` alone left an absolute CodeView PDB path and made bytes depend on the checkout directory. **Impact →** independent hosted builds reproduce path-independent DLL bytes.
- **Decision →** Tag the exact qualified commit, then make release-status documentation a later commit. **Why →** changing the release commit after artifact qualification would invalidate the manifest/commit binding. **Impact →** tag `v1.0.0` remains at `53f787b4489f487fa5dcf86af227510fc4ebc029`; current `main` may contain later documentation-only truth updates.

## Problems found

The original GPL decision conflicted with the DNG-bearing native dependency. Changing OmniBrille to MIT removed that GPL-specific conflict but did not resolve the owner's refusal to distribute DNG, so publication remained blocked until the native code was actually removed. No suitable DNG-free official replacement was found among the compatible packages inspected. The first reproducible-build claim also missed the absolute PDB path; independent review found it before release, and the final package fixed and re-proved it. No blocker remains for the advertised Standalone-first Windows x64 contract.

The historical public `v0.8.0-preview.2` predates an explicit project license and remains unchanged. It deserves separate owner/legal review; this release did not rewrite or delete historical assets.

## What the agents learned

- **Promoted:** native reproducibility includes embedded paths, not only timestamps. Independent inspection and separate hosted builds supported promotion into `/PDBALTPATH`, binary/provenance/package checks, and [`native-skia.md`](../native-skia.md).
- **Promoted:** removal of a refused dependency must be proven through source acquisition, build closure, binary content, resolved/published/installed identity, and notices. Independent Architecture/Packaging and adversarial evidence supported the build scripts, tests, manifest fields, and installed-artifact gates.
- **Remain candidate:** broaden the absolute-PDB-path detector beyond drive-letter paths when the native recipe is next changed. The accepted bytes received an additional broad scan, so changing the gate now would have added churn without improving this frozen release.
- **Rejected:** make the temporary screenshot/qualification harness's spaced-path quoting mistake a permanent project rule. It was a one-off ignored harness issue, corrected during the run, with no product effect.
- **Rejected:** treat one automation harness close-request anomaly as a product defect. Normal `WM_CLOSE`, repeated local relaunch, and the independent hosted normal-close gate passed.
- Architecture/Packaging, Performance, UX/visual review, Implementation, Documentation, and independent Adversarial Review were useful. Product strategy and AX specialists were unnecessary because the release contract and product behavior did not change. Targeted handoffs avoided rereading broad history.
