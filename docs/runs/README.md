# Significant run reports

Reports here are historical snapshots of what a substantial run claimed, changed, and validated at the time. They support later archaeology; they are not current architecture or mandatory default context.

Retain a report only for architecture/product boundary changes, serious regressions, release qualification, durable engineering infrastructure, or evidence likely to matter later. Trivial edits do not get reports.

- Current behavior and architecture remain authoritative in [`README.md`](../../README.md) and [`docs/architecture.md`](../architecture.md).
- If a later run disproves an old claim, do not rewrite the old report. Correct current authority and record the later discovery.
- Use the owner template and learning rules in [`learning-and-reports.md`](../engineering/learning-and-reports.md).
- Future agents should load a report only for a specific historical claim, regression, release, or validation environment.
