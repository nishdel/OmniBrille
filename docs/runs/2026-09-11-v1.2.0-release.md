## Important technical decisions

- **Normal integration and immutable release identity.** Preserve PR #11 commits and published history with a fast-forward from the recorded main baseline when still possible. Qualify a clean source commit before publishing main, tag that exact main commit with annotated `v1.2.0`, and build public assets by dispatching the existing release workflow at the tag. Remote main, peeled tag, workflow head and artifact manifest must agree before publication.
- **One artifact family.** The local verifier and ordinary CI qualify source/package machinery. Public installer, checksum, manifest, dependency inventory, generated notes and validation JSON must come from one successful tagged release workflow. Installer timestamps vary; mixing separately built files would invalidate the checksum evidence.
- **Unsigned distribution with explicit limits.** Continue the established unsigned mode; do not change credentials, pinned dependencies, licenses, installer identity, or signing policy. Public notes disclose Unknown Publisher/SmartScreen and distinguish checksum integrity from publisher authentication.
- **No publication-only source commit.** Write release-safe current docs before freezing source. Record final dynamic hashes and workflow outcomes on GitHub and in the release assets so final main remains exactly the tagged/released commit.

## Validation and confidence

**Verified incoming candidate:** Windows 304 ordinary + 72 headless tests passed with one Unix-specific skip; Ubuntu passed all 305 ordinary + 72 headless tests. Both CI jobs passed; Windows built an installer. Four software captures were inspected during the issue audit. These are candidate results, not a substitute for the final release checks.

**Final release evidence:** `build/verify-release.ps1` is the clean-tree gate for restore, formatting, analyzer-enabled Release build, the full suite, vulnerability review, informational dependency updates, documentation/link checks, package generation, contents/licenses/native/Voice hashes, version/signature/manifest/sidecar/notes agreement, and diff hygiene. The tagged workflow repeats this gate after native provenance rebuild and sends the exact installer to a separate checkout-free Windows lifecycle job. Its `OmniBrille-release-validation.json` records fresh install, registration, version/signature, Light launch, normal close, Dark relaunch, uninstall and cleanup. Final counts and outcomes must be read from that release's workflow and assets rather than inferred from incoming candidate evidence.

**Not verified by those gates:** native control/transition feel; real microphone and room-noise behavior; concept/visual acceptance; motion comfort and native readability; physical sound character; extreme text-scale dense layouts; real screen-reader/high-contrast/DPI/GPU behavior; a current OmniSorSe host; interactive Linux/macOS; and an in-place upgrade using the final public bytes. Issues #3–#7 retain the relevant manual acceptance. These are not known implementation blockers or claims of completed tests.

**Inferred:** the unchanged installer ownership and protocol/privacy contracts support continuity with prior versions, but this does not turn historical upgrade or host evidence into v1.2.0 validation.
